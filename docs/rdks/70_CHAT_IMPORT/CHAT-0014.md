## Sammenhæng
Denne chat dokumenterer stabiliseringen af RavRadar 4.0.117, fejlsøgningen af DKSS/Limfjord-strøm, korrektionen af U/V-parring på vertikallag, administratorens rettelser af land-/havpunkter og kystlinjer, produktionsverifikation samt beslutningen om at flytte den videre udvikling til Codex.

## Udtrukne hovedtemaer
- Arbejdet skal udføres systemisk – hele runtime- og releasekæden skal tænkes som ét system, ikke som isolerede tests eller filer.
- Lokal grøn validering er ikke det samme som CI- eller produktionsverifikation. En baseline må først betegnes som stabil, når den relevante friske produktionskæde er verificeret.
- DMI-strømkomponenter skal parres på samme fysiske gitterpunkt, forecasttid og vertikallag. Flere DKSS-dybdelag må ikke overskrive hinanden i kandidatcache.
- Administratorredigeret zonegeometri er autoritativ central konfiguration. Gemte kystlinjer samt land-/havpunkter skal propagere fra Supabase gennem DMI, cache, score og offentlig runtime uden kodeændringer.
- Tre Limfjordszoner blev manuelt korrigeret i admin, fordi deres geometri var forkert. Den efterfølgende friske produktionskørsel bekræftede, at ændringerne blev hentet og anvendt.
- 4.0.117 commit `6c1dece72d5970a1fc095b9a22f080d811cd9f36` blev efter tidligere fejlede forsøg efterfølgende kørt succesfuldt i produktion; run #1750 er den friske verifikation efter adminrettelserne.
- Forecastets yderste horisont kan fortsat have manglende strøm/vandstand i enkelte timer/zoner. Det er et separat dækningsproblem og må ikke maskeres med stale data eller fysisk nul.
- Codex skal arve projektets aktuelle viden gennem AGENTS, RDKS, håndbog, AI-dokumentationspakken, tests, Git-historik og chatarkivet. Historiske chats er begrundelse, ikke automatisk aktuel sandhed.

## Importregler
Denne chat er historisk evidens efter import. Aktuel brugerbeslutning, aktive RDKS-poster og verificeret kode/produktion har højere autoritet. Hvis en senere beslutning erstatter noget herfra, skal den senere beslutning vinde og historikken bevares.
